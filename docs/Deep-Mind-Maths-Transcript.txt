TernOO-5500FP — Mathematical Research Brief
TMesh Triangular Lattice: Mutual Recovery, Traversal Products, and Content Identity

CONTEXT — WHAT WE ARE BUILDING
TernOO-5500FP is a balanced ternary computing architecture. The core
addressing model uses two complementary structures:
TMesh — a triangular/tetrahedral lattice used for content
identification and object traversal. Each triangle in the mesh has
three sides, each side is a content chunk, and the identity of each
chunk can be recovered by hashing the other two (mutual recovery
property).
OTree — an octree coordinate space used for representing objects
as three-dimensional structures in the object model.
MMID (Minimal Map ID) — the minimal identifier for an object.
The starting point for traversal through the TMesh.
MMOE (Minimal Map Object Entity) — the full object representation,
arrived at by completing the traversal from the MMID.
The working hypothesis: an object's identity (MMID) is the minimal
description from which the full object (MMOE) can be reconstructed
by traversing the TMesh. The traversal IS the reconstruction. No
separate storage or retrieval step is needed — the object emerges
from the path through the mesh.

THE CORE INTUITION — STATED IN PLAIN LANGUAGE

Every program or object can be represented as a unique serialised
string of trits (balanced ternary digits: -1, 0, +1).
The TMesh is a lattice of triangles. Each triangle has three sides.
Each side is a content chunk of the object being represented.
The mutual recovery property: knowing any two sides of a triangle,
the third side can be recovered by hashing the two known sides.
This is not assumed — it is one of the core questions of this brief.
Traversal works as follows:

You enter a triangle having already traversed two of its sides
(you have accumulated those two content chunks)
You hash the two known sides to recover the third
You now have all three sides of the triangle
You multiply them together to get the content unit for that triangle
You carry the accumulated product forward and move to the next triangle
At each bifurcation (two possible next triangles) you use a
bubble-sort-style comparison to choose the path that halves your
distance to the target — navigating by pattern proximity, not by
arbitrary coordinate


The bubble sort navigates. The mutual hash completes each triangle.
The multiplication accumulates the content. These are three separate
operations serving three separate purposes.
The object is not pre-divided into chunks. The chunks emerge from
the traversal path. The object is reconstructed by the traversal,
not retrieved from storage.
Content identity: two objects that produce the same traversal path
through the mesh ARE the same object. The mesh address is not a
pointer to the object — it IS the object's identity.

Important caveat: The above is a working hypothesis, not an
established fact. All of the questions below are genuinely open.
The goal of this consultation is to determine whether the hypothesis
is mathematically sound, and if not, what the correct formulation is.

QUESTION 1 — THE MUTUAL RECOVERY PROPERTY
The hypothesis: for three content chunks A, B, C arranged as the
sides of a triangle, knowing any two recovers the third.
Formally: does there exist an operation ⊕ such that:
A ⊕ B = C
B ⊕ C = A
A ⊕ C = B
hold simultaneously — not as a convention but as a mathematical identity?
1a. In binary, XOR satisfies this property: if A XOR B XOR C = 0,
then each value is recoverable from the other two. Does an analogous
operation exist in balanced ternary (values in {-1, 0, +1} or
integers mod 3^n)? If yes, what is it? If no, what is the closest
available substitute and what properties does it preserve or lose?
1b. The three cube roots of unity satisfy 1 + ω + ω² = 0, meaning
their sum is zero. Is the sum-to-zero property the correct algebraic
foundation for mutual recovery in the ternary case? If A + B + C = 0
in some appropriate number system, does that guarantee each is
recoverable from the other two? What number system makes this
meaningful for content chunks?
1c. Is the finite field GF(3^6) — which has 729 elements and full
field arithmetic — a suitable algebraic structure for this property?
Does it provide the mutual recovery operation, and if so what is the
operation explicitly?

QUESTION 2 — THE TRAVERSAL PRODUCT
The hypothesis: at each triangle during traversal, multiplying the
three side values together produces a content unit, and accumulating
these products across a complete traversal path reconstructs the
original object.
2a. Is there a mathematical structure in which the accumulated
product of triangle side-triples along a traversal path converges to
a unique representation of the target object? If yes, what are the
conditions on the chunk values and the traversal path for this to hold?
If no, is there an alternative accumulation operation (sum, XOR-analogue,

2b. The hypothesis tentatively suggests each triangle side is

2c. Is the accumulated product invertible — that is, given the

2d. If multiplication is not the right operation, what property
should the accumulation operation have? Specifically: it should
combine information from successive triangles in a way that is
order-sensitive (path-dependent), non-repeating (DAG property), and
reconstructible. What operations satisfy these constraints in
balanced ternary arithmetic?

QUESTION 3 — THE BUBBLE SORT NAVIGATION
The hypothesis: at each bifurcation in the mesh, comparing the

3b. The navigation comparison is done on chunk values, not on

1. Why “negative‑sum” is the right analogue
1.1 What XOR really is

In binary, XOR is just addition modulo 2:

a  XOR  b  =  (a+b) mod 2.a\;\text{XOR}\;b\;=\;(a+b)\bmod 2 .aXORb=(a+b)mod2.

Because the additive group (Z/2Z,+)(\mathbb Z/2\mathbb Z,+)(Z/2Z,+) has the special property that each element is its own inverse:

a=−a(mod 2),a = -a\quad(\text{mod }2),a=−a(mod 2),

the XOR operation automatically satisfies

(a⊕b)⊕b=a,(a⊕b)⊕a=b.(a\oplus b)\oplus b = a,\qquad (a\oplus b)\oplus a = b .(a⊕b)⊕b=a,(a⊕b)⊕a=b.

That is exactly the “any‑two‑sides‑recover‑the‑third” requirement.
1.2 What changes in characteristic 3?

In a 3‑ary additive group (ℤ/3ⁿℤ or GF(3ⁿ)) the additive inverse is not the element itself:

−a≡2a(mod3)(or in the field, −a=2a).-a \equiv 2a \pmod{3}\quad\text{(or in the field, }-a = 2a\text{)} .−a≡2a(mod3)(or in the field, −a=2a).

Consequently the plain sum A+BA+BA+B does not give us the recovery property:

(A+B)+B=A+2B≠Ain general.(A+B)+B = A+2B\neq A\quad\text{in general}.(A+B)+B=A+2B=Ain general.

If we first take the additive inverse of the sum, we obtain an operation that does have the desired self‑cancellation behaviour:

A⊕B  :=  −(A+B).\boxed{A\oplus B \;:=\; -(A+B)} .A⊕B:=−(A+B)​.

Now compute:

(A⊕B)⊕B=−(−(A+B)+B)=−(−A−B+B)=−(−A)=A.\begin{aligned} (A\oplus B)\oplus B &= -\bigl(-(A+B)+B\bigr) \\ &= -\bigl(-A - B + B\bigr) \\ &= -(-A) = A . \end{aligned}(A⊕B)⊕B​=−(−(A+B)+B)=−(−A−B+B)=−(−A)=A.​

The same calculation works for the other two equations, so the three‑way recovery holds for every triple that satisfies C=−(A+B)C = -(A+B)C=−(A+B).

x⊕y  =  −(x+y)x\oplus y \;=\; - (x+y)x⊕y=−(x+y)

Commutative 	x⊕y=y⊕xx\oplus y = y\oplus xx⊕y=y⊕x 	obvious because addition is commutative
Idempotent 	x⊕x=xx\oplus x = xx⊕x=x 	−(x+x)=−2x=x-(x+x) = -2x = x−(x+x)=−2x=x in characteristic 3 (since −2≡1-2 \equiv 1−2≡1).

5. Practical implementation for the 6‑trit “tribble”

Your prototype works with 6‑trit words (values 0 … 728).
A convenient implementation in Python (or any language that can handle integers) is:

MOD = 3**6                # 729
MASK = MOD - 1            # 0b101101101101 (if you like bit tricks)

def ternary_op(a: int, b: int) -> int:
    """Negative‑sum operation for 6‑trit tribbles."""
    s = (a + b) % MOD          # ordinary modular sum
    return (-s) % MOD          # additive inverse (same as MOD - s)
    # equivalently: return (MOD - s) % MOD

If you are already using the field representation (e.g. via a library that implements GF(3⁶) with a primitive polynomial), you can write:

def ternary_op_field(a, b):
    # a, b are field elements; the library overloads + and *.
    return 2 * (a + b)   # 2 is the field element -1

Both versions satisfy:

C = ternary_op(A, B)
assert ternary_op(B, C) == A
assert ternary_op(A, C) == B

Because the operation is bijective in each argument, you can also use it for hash‑like mixing: the map b ↦ A⊕b is a permutation, which is a useful property for collision‑resistance arguments.
