## Preamble

This document specifies the TernOO word architecture as implemented on the 5500FP
24-trit balanced-ternary processor. It deliberately diverges from the SBTCVM
Gen2-9 TernOO implementation wherever the 5500FP's richer architecture permits a
superior design.

The central thesis is unchanged from v0.1, and is now **built**: **every 24-trit
word is self-describing.** A word's header trits encode not just its type but its
full operational semantics — calling convention, spatial coordinates, scalar
encoding, pointer model, opcode family and arity, and in the most general case its
own code segment, data segment, and internal cursor. Object dispatch requires no
vtable lookup, no runtime type check, and no memory cycles beyond the fetch of the
word itself.

This is not object-oriented programming layered on top of a machine. It is
object-oriented structure intrinsic to the machine word.

What v0.1 could not yet express — a nine-type primary space, an opcode instruction
word, and the TTree/OTree content-addressed mesh (MMID → MMOE) that makes objects
*computed from coordinates* rather than stored — is the substance of this revision.

Trit convention throughout: **N = −1, Z = 0, P = +1** (also written −, 0, +).
Trit positions are numbered **T0 (LSB) through T23 (MSB)**.

## 1. The 24-Trit Word — the 2+4+18 layout

All memory locations and registers hold 24-trit balanced-ternary words. The word
is divided into three functional regions:

```
 T23 T22 │ T21 T20 T19 T18 │ T17 ........................ T0
 ────────┼──────────────────┼──────────────────────────────
 PRIMARY │     QUALIFIER     │            PAYLOAD
 (2 trits)│     (4 trits)     │           (18 trits)
 type ID  │   type grammar    │   value / address / structure
```

Field-position constants (`5500fp_ternoo_v03.py`):

| Region    | Trits      | Width | Constants                          |
|-----------|------------|-------|------------------------------------|
| PRIMARY   | T23–T22    | 2     | `PRIMARY_MST=23`, `PRIMARY_LST=22` |
| QUALIFIER | T21–T18    | 4     | `QUAL_MST=21`, `QUAL_LST=18`       |
| PAYLOAD   | T17–T0     | 18    | `PAYLOAD_MST=17`, `PAYLOAD_LST=0`  |

Word-scale constants: `WORD_TRITS = 24`; `WORD_MAX = (3²⁴−1)/2 = 141,214,768,240`;
`WORD_MIN = −WORD_MAX`; `TRYTE_MAX = (3⁶−1)/2 = 364`.

Every accessor delegates to two field primitives — no ad-hoc bit/trit twiddling:
- `get_field(value, lsb, width)` = the `width` balanced trits of `value` starting
  at position `lsb`, returned as a balanced integer.
- `set_field(value, lsb, width, field)` = `value` with those trits replaced.

Named accessors: `get_primary`/`set_primary` (lsb 22, width 2),
`get_qualifier`/`set_qualifier` (lsb 18, width 4), `get_payload`/`set_payload`
(lsb 0, width 18). `_make_word(primary, qualifier, payload)` assembles a word from
three `set_field` calls.

**Primary encoding detail:** the primary is a balanced **2-trit** integer with T22
as the low trit and T23 as the high trit — `primary = T22 + 3·T23`, spanning
−4..+4. This matters for backward compatibility (§14): every legacy 1-trit
EXEC/MAP/DATA word carried its type in T23 with T22 = −1, so the 2-trit reader
decodes legacy words correctly.

## 2. The Nine PRIMARY Types (T23–T22)

The primary is decoded first and is architecturally invariant — no format
extension may relocate or reinterpret it (Principle P1). Nine (T23,T22)
combinations give nine primary types:

| Constant          | (T23,T22) | int | Name (`PRIMARY_NAMES`) | Status                         |
|-------------------|-----------|-----|------------------------|--------------------------------|
| `PRIMARY_EXEC`    | (−1,−1)   | −4  | EXEC                   | live                           |
| `PRIMARY_MAP`     | (−1, 0)   | −3  | MAP                    | live                           |
| `PRIMARY_DATA`    | (−1,+1)   | −2  | DATA                   | live                           |
| `PRIMARY_NEURAL`  | ( 0,−1)   | −1  | NEURAL                 | defined, dormant               |
| `PRIMARY_IO`      | ( 0, 0)   |  0  | I/O                    | defined, dormant               |
| `PRIMARY_CRYPTO`  | ( 0,+1)   | +1  | CRYPTO                 | reserved (name only)           |
| `PRIMARY_OPCODE`  | (+1,−1)   | +2  | OPCODE                 | live (alias of retired OPEN_A) |
| `PRIMARY_OPEN_B`  | (+1, 0)   | +3  | OPEN_B                 | open (name only)               |
| `PRIMARY_POOL`    | (+1,+1)   | +4  | POOL                   | reserved (dynamic allocation)  |

`PRIMARY_OPCODE = PRIMARY_OPEN_A` — the OPEN_A slot was retired in favour of a
first-class OPCODE type; `PRIMARY_NAMES` maps the `(+1,−1)` slot to `'OPCODE'`.

Each primary carries a 4-trit qualifier → **3⁴ = 81 qualifier states per primary**
(where v0.1's 3-trit qualifier gave only 27).

---

## 3. The QUALIFIER Field (T21–T18)

The four qualifier trits refine meaning **within** each primary; their grammar is
therefore per-type. Qualifiers are assembled LSB-first as
`from_trits([T18, T19, T20, T21])`. The grammars:

- **EXEC** — T21 privilege, T20 call-style, T19 return-type, T18 segment-index MSB.
- **MAP** — T21 axis-YZ, T20 axis-XZ, T19 axis-XY, **T18 mode_hint** (the
  TTree/OTree discriminator, §6).
- **DATA** — T21–T20 secondary type (SCALAR/POINTER/STRING or a pointer model),
  T19 sub-encoding.
- **OPCODE** — T21–T20 family, T19–T18 arity.
- **NEURAL / I/O** — selector + mode trits (dormant grammars, defined below).
- **CRYPTO / OPEN_B / POOL** — no grammar yet (name-only slots).

---

## 4. The PAYLOAD — three tribbles (T17–T0)

The 18-trit payload is read as **three 6-trit tribbles** (a "tribble" is a
balanced 6-trit tryte, range ±364). `extract_tribbles(word)` returns:

| Tribble | Trits    | `get_field`        | Role (typical)                       |
|---------|----------|--------------------|--------------------------------------|
| `ta`    | T17–T12  | `get_field(w,12,6)`| high tribble — symbol ID / Y / op-idx|
| `tb`    | T11–T6   | `get_field(w, 6,6)`| mid tribble  — Z / immediate          |
| `tc`    | T5–T0    | `get_field(w, 0,6)`| low tribble  — meccano value / immed. |

The tribble decomposition is what lets a whole word participate in the content
mesh: symbol IDs are packed **high** (into `ta`) so they weigh into the OTree fold
(§10). The primary and qualifier are excluded from tribble extraction — only the
18-trit payload folds.

## 5. EXEC Words (primary EXEC)

An EXEC word references executable code and encodes its complete calling contract
in the qualifier, so call-site compatibility is verifiable at fetch time.

```
 EXEC │ T21=PRIVILEGE  T20=CALL-STYLE  T19=RETURN-TYPE  T18=SEGIDX-MST │ payload=address
```

- **T21 privilege:** `EXEC_PRIV_KERNEL=−1`, `EXEC_PRIV_USER=0`, `EXEC_PRIV_SANDBOX=+1`
- **T20 call-style:** `EXEC_CALL_STACK=−1`, `EXEC_CALL_REGISTER=0`, `EXEC_CALL_MESSAGE=+1`
- **T19 return-type:** `EXEC_RET_EXEC=−1`, `EXEC_RET_MAP=0`, `EXEC_RET_DATA=+1`
- **T18 + T17:** the code-segment index, split MSB-in-qualifier / LSB-in-payload,
  stored balanced as `seg_idx − 4`.

This gives **typed function pointers** — privilege, calling convention, and return
type checkable at the hardware word level, without a separate function descriptor.
`build_exec_word(privilege, call_style, return_type, seg_idx, offset)`.

## 6. MAP Words (primary MAP) — the octree and the TTree/OTree mesh

A MAP word encodes a position in an octree coordinate frame. Each of the three
qualifier axis-trits encodes directional sense along one axis pair; a fourth
qualifier trit (T18) is the **mode_hint**.

```
 MAP │ T21=axis-YZ  T20=axis-XZ  T19=axis-XY  T18=mode_hint │ payload=coordinate
```

Axis trit: −1 = negative/below, 0 = on-plane/at-boundary, +1 = positive/above.
`build_map_word(axis_yz, axis_xz, axis_xy, payload, mode_hint=0)`.

`decode_map_word` derives a **mode from the number of zero axis-trits** — the
redundant-zero economy of balanced ternary put to work as a scale/scope anchor:

| Zero axes | Mode          | Payload interpretation                    |
|-----------|---------------|-------------------------------------------|
| 3         | `ORIGIN`      | scale                                     |
| 2         | `ON_AXIS_{X/Y/Z}` | value along the single live axis      |
| 1         | `ON_PLANE`    | two 9-trit half-coordinates               |
| 0         | `ABSOLUTE_3D` | full (yz, xz, xy, magnitude)              |

### 6.1 Two coordinate systems in one word — TTree and OTree

The **mode_hint (T18)** discriminates the two roles a MAP word can play:

- **TTree (mode_hint = +1 → `ON_PLANE`) — structural identity, "what kind of
  thing."** Built by `build_ttree_mmid(ta, tb)`: `ta` (structural role) packs into
  payload trits 9–17, `tb` (interaction style) into 0–8. A TTree word is
  **type-determined and position-independent** — two objects of the same type have
  the same TTree word.
- **OTree (mode_hint = 0 → `ABSOLUTE_3D`) — content address, "this exact content."**
  Built by `build_otree_mmoe(tribble_state)`: octant signs are derived from
  `state%3`, `(state//3)%3`, `(state//9)%3` (each 0 coerced to +1 so all axes are
  live), and `magnitude = state % 729`. Content-addressable: the same content-fold
  always lands at the same coordinate.

This duality is the heart of GristMill (§10): an object's *identity* is its TTree
word (the **MMID**), and its *placement* is its OTree word — the object is not
stored at an address, it is **computed** from its coordinate.

### 6.2 MAP use cases

Polygon-mesh vertices; P2PCP node addressing (REMOTE pointers, §7); octree spatial
indices; FlowCode symbol placement; CGP mandate geographic scope.

## 7. DATA Words (primary DATA)

DATA words carry values, pointers, and strings. The secondary type sits in T21–T20;
a tertiary trit (T19) refines it.

### 7.1 SCALAR (`DATA_SCALAR`, (T21,T20)=(−1,−1))
- **T19 encoding:** `SCALAR_FLOAT=−1` (fixed-point), `SCALAR_INT=0` (balanced
  ternary native), `SCALAR_UINT=+1` (unsigned).
- Payload: an 18-trit scalar value.

### 7.2 STRING (`DATA_STRING`, (T21,T20)=(+1,−1))
- **T19 encoding:** `STRING_UNICODE=−1` (UTF-8 compatible), `STRING_ASCII=0`
  (byte sequence), `STRING_TERNARY=+1` (native ternary glyph — the char-map plane).
- Payload: inline length (short strings) or an address of string data.

### 7.3 POINTER (`DATA_POINTER`, (T21,T20)=(0,0)) — nine models
The pointer subtype uses T21–T20 to select one of nine pointer models. Eight are
predefined; the ninth is the user-defined self-describing object word.

| Model            | (T21,T20) | Description                                  |
|------------------|-----------|----------------------------------------------|
| `PTR_FLAT`       | (−1,−1)   | direct memory address                        |
| `PTR_RELATIVE`   | (−1, 0)   | offset from the program counter              |
| `PTR_STACK_REL`  | (−1,+1)   | offset from the stack pointer                |
| `PTR_FIELD`      | ( 0,−1)   | object base + field index                    |
| `PTR_NULL`       | ( 0, 0)   | null / undefined reference                   |
| `PTR_SYMBOL`     | ( 0,+1)   | interned symbol (hash / table index)         |
| `PTR_REMOTE`     | (+1,−1)   | network node reference (P2PCP address)       |
| `PTR_WEAK`       | (+1, 0)   | weak reference (GC-transparent)              |
| `PTR_USER_DEF`   | (+1,+1)   | user-defined self-describing object (§7.4)   |

`PTR_SYMBOL` is the model behind all SHAPE / STYLE / LAYOUT / SIGNAL operands
(§9): the symbol ID rides in `ta` (T17–T12), placed high so it folds into the
object's content address.

### 7.4 The Self-Describing Object Word (`PTR_USER_DEF`)
The user-defined pointer encodes a complete object descriptor — subclass, internal
cursor, code segment, and data segment — in one 24-trit word:

```
 DATA │ PTR_USER_DEF │ T17-T16=SUBCLASS │ ta/tb/tc-style fields: OFFSET · CODE-SEG · DATA-SEG
```

- **Subclass** (2 trits): nine variants, the `(+1,+1)` variant reserved for further
  user extension (Principle P4).
- **OFFSET** (6 trits, ±364): an internal cursor for sequential/streaming access
  within the object's data — an instruction pointer for the object's own data.
- **CODE-SEG** (6 trits): a compact reference to the object's method code, resolved
  at dispatch via a code-segment base register. The method table in a single tryte.
- **DATA-SEG** (6 trits): a compact reference to the object's data storage, resolved
  via a data-segment base register.

**Dispatch:** read CODE-SEG → resolve; read DATA-SEG → resolve; read OFFSET → set
cursor; branch. No fetches beyond the word itself. **The word IS the object** — a
complete process-launch descriptor, Alan Kay's "each object is a computer" at the
hardware word level.

## 8. OPCODE Words (primary OPCODE) — the instruction word

The OPCODE primary (new since v0.1) turns the self-describing word into an
executable instruction. Its qualifier splits into **family + arity**, and its
payload into **op-index + immediate**:

```
 OPCODE │ T21-T20=FAMILY  T19-T18=ARITY │ T17-T12=OP-INDEX │ T11-T0=IMMEDIATE(FORM)
```

- **ARITY (T19–T18):** stored as `arity − 4` in a balanced 2-trit field, carrying
  operand counts **0..8**. The stream walker reads exactly `arity` words after the
  opcode as its operands — this is how a flat word stream carries structured
  instructions with their arguments (operand chaining).
- **OP-INDEX (T17–T12):** 6 trits, the operation within the family.
- **IMMEDIATE / FORM (T11–T0):** 12 trits, the variant discriminant (§8.3).

`build_opcode_word(family, arity, op_index, immediate, meccano=None)` /
`decode_opcode_word(word)`.

### 8.1 Opcode families (`OPF_*`, (T21,T20))

| Family          | (T21,T20) | int | Members                                        |
|-----------------|-----------|-----|------------------------------------------------|
| `OPF_ISA_CORE`  | (−1,−1)   | −4  | the core ISA ops (arithmetic, load/store, jumps) |
| `OPF_ISA_STACK` | (−1, 0)   | −3  | JSR / RTI / PUSH / POP                         |
| `OPF_WORD_OP`   | (−1,+1)   | −2  | TOBJ / TGET / TPAYLOAD / TCALL / TNEW / TBUILD / TSEG |
| `OPF_PIGART`    | ( 0,−1)   | −1  | RPOINT / RLINE / RNODE / REDGE / RENDER        |
| `OPF_MECCANO`   | ( 0, 0)   |  0  | meccano-value programs                          |
| `OPF_MODEL`     | ( 0,+1)   | +1  | MKIND / MNAME / MCELL / MCMDW / MPARM / MPORT / MSCOPE / MMORE / MEDGE / MFLAG / MNOTE |

**Six live families; three (+1,·) slots reserved.** `OPF_MODEL` (added 3 Jul 2026)
carries program-model attributes so the word stream conveys the *program*, not
merely its rendering.

### 8.2 Meccano and the WORD_OP dispatcher
- **MECCANO** words carry a value in the **low tribble `tc` (T5–T0)** — 0 or a
  multiple of 27, normalised mod 729 — while `ta`/`tb` are spare. `meccano_tribble`
  reads `tc`, not `ta`.
- **WORD_OP** provides the Layer-2 object dispatcher: `TOBJ`, `TGET`, `TPAYLOAD`,
  `TCALL`, `TNEW`, `TBUILD`, `TSEG` construct, inspect, and dispatch on the
  self-describing words above.

### 8.3 RNODE / REDGE and the FORM field (PIGART)
The PIGART family renders FlowCode/GUI graphs. `OP_RNODE` (Render Node) and
`OP_REDGE` (Render Edge) emit an opcode word followed by an operand chain whose
length is the arity:

- **RNODE** operands: `MAP(position), DATA(dims), SYMBOL(shape) [, UDP]
  [, N×STRING label] [, SYMBOL(layout)]` — the layout symbol is always last.
- **REDGE** operands: `MAP(src), MAP(dst) [, SYMBOL(style)] [, N×STRING label]`;
  the handler form `build_redge_handler(src, dst, signal)` emits exactly five words
  binding a SIGNAL to a STYLE_HANDLER.

The **FORM** immediate selects the operand shape: `FORM_LEAN=0`, `FORM_SHAPE=1`,
`FORM_SHAPE_UDP=2`, `FORM_HAS_LAYOUT=4` (bit), with combinations
`FORM_SHAPE_LAYOUT=5`, `FORM_SHAPE_UDP_LAYOUT=6`, and `FORM_HANDLER=−1`.

`iterate_instructions(words)` is the stream walker: skip non-OPCODE words; for each
opcode, take `words[i+1 : i+1+arity]` as operands and advance `i += 1 + arity`.

> **Encoding quirk (kept deliberately):** `OP_RNODE = 40`, but `OP_REDGE = −1` and
> `OP_RENDER = −2` use negative op-index encodings — a v0.3 artefact preserved for
> compatibility. The identifiers are `OP_RNODE`/`OP_REDGE`, not
> `OPCODE_RNODE`/`OPCODE_REDGE`.

## 9. NEURAL, I/O, and the reserved primaries; symbol families

**NEURAL** (dormant grammar): T21 selects `NEURAL_UNIT=−1`, `NEURAL_CONNECTION=0`,
`NEURAL_STRUCTURE=+1` — the substrate for GHOST/PIGART neural mesh words.

**I/O** (dormant grammar): T21 direction (`IO_DIR_IN/BIDI/OUT`), T20 buffering
(`IO_BUF_NONE/BUFFERED/INTERRUPT`), T19 blocking, T18 spare.
`build_io_word(...)`.

**CRYPTO, OPEN_B, POOL** are reserved name-only slots — no qualifier grammar and no
constructors yet. CRYPTO anticipates the `ternary_sponge` / MMID-security work;
POOL anticipates dynamic word allocation; OPEN_B is the deliberate escape hatch.

**Symbol families** (DATA-POINTER-SYMBOL words, ID in `ta`):
- **SHAPE** 0–12: RECTANGLE, TERMINATOR, PROCESS, DECISION, IO, SUBROUTINE,
  CONNECTOR, OFFPAGE, DOCUMENT, DATA, LABELED_BOX, WINDOW, BUTTON (13–26 reserved,
  27+ community).
- **STYLE** ≥ 100: `STYLE_CONTAIN=100` (logical containment, no render),
  `STYLE_HANDLER=101` (signal→handler binding). Renderers suppress IDs ≥ 100.
- **LAYOUT** 200–204: ABSOLUTE, HBOX, VBOX, GRID, STACKED.
- **SIGNAL** 300–307: CLICKED, TOGGLED, CHANGED, ACTIVATED, CLOSE_REQUESTED,
  FOCUS_CHANGED, VALUE_CHANGED, SELECTION_CHANGED.

## 10. The Mesh Mathematics — Steiner quasigroup, MMID/MMOE, the Fingerprint Fold

Objects are not stored at addresses; they are **synthesised from coordinates**
(the GristMill engine). The mesh runs on one operation.

**The Steiner quasigroup:** `MOD = 3⁶ = 729` ("one tribble"), and
```
ternary_op(a, b) = (−(a + b)) mod 729
```
Mutual-recovery invariant: if `C = ternary_op(A, B)` then `ternary_op(B, C) = A`
and `ternary_op(A, C) = B`. Any side is recoverable from the other two — a
self-validating mesh. `MECCANO_VOCAB = {27, 54, …, 702}` is the closed 27-element
sub-quasigroup (a closed subset of Z/729Z must have size 3ᵏ; the multiples of 27
qualify).

**Traversal:** `traverse_step(state, a, b)` recovers `side_c = ternary_op(a, b)`,
advances `state = (state + side_c) mod 729`, and reports arrival when
`side_c == 0` (the end-of-object sentinel). `vocab_step` adds DAG ordering.

**MMID → MMOE (GristMill):**
- An **MMID** (Minimal Map ID) is a TTree MAP word — a structural coordinate. Two
  same-type objects share an MMID; identity is type, not instance. `distance_to`
  is the trit-weight of the tribble differences (ternary Hamming, Kademlia lineage,
  range 0..12).
- An **MMOE** (Minimal Map Object Entity) is the object synthesised at an OTree
  coordinate. Its canonical word stream is `[TTree MAP, (OTree MAP if placed),
  UDP, *exec_words, *children]`.
- `GristMill.compose(mmids)` threads the fold: `S = (S + ternary_op(ta, tb)) mod
  729` per element, placing each object at `build_otree_mmoe(S)`. Same sequence →
  identical stream (content-addressable, deterministic).

**The Fingerprint Fold** (a program's content hash) is position-weighted:
```
S = 0
for i, word in enumerate(words):
    ta, tb, _ = extract_tribbles(word)
    S = (S + ternary_op(ta·(i+1), tb)) mod 729
address = build_otree_mmoe(S)
```
Because symbol IDs live in `ta` and the weight is `ta·(i+1)`, changing any
shape/style/layout/signal — or its position — changes the program's address. This
is the substrate the earn-unit's mint work runs on (P2PCP; see the manifold §5
docket).

## 11. Design Principles

**P1 — Primary-trit invariance.** T23–T22 always identify the primary type; no
extension may relocate or reinterpret them. The fetch-decode loop has a stable
2-trit entry point.

**P2 — Self-description without lookup.** Every word type carries enough metadata
to initiate its operation with no extra memory cycles — no vtable, no descriptor
table, no runtime type check.

**P3 — Redundant zeros as semantic anchors.** Zero states in qualifier trits are
not wasted: origin, on-plane, scale level, null, arrival sentinel. The natural
economy of balanced ternary.

**P4 — Escape hatch preserved.** In every extensible category a `(+1,+1)`
combination (or the OPEN_B primary) is reserved for user extension. Forward
compatibility is structural, not contractual.

**P5 — No SBTCVM compromise inherited.** The nine-primary space and the
DATA/POINTER/USER-DEFINED taxonomy derive from 5500FP properties, not SBTCVM's
opcode-in-negative-range convention.

**P6 — Economics from structure, not compression.** MAP words encode 3D position
as directional sense (qualifier) + magnitude (payload) — intrinsically denser than
enumerating coordinates, the same way vector graphics beat bitmaps.

**P7 — Objects computed, not stored.** TTree identity + OTree content-address means
the address IS the object's content-fold; GristMill synthesises the MMOE from the
MMID rather than fetching it. Storage is a fold, not a table.

## 12. Relationship to the 5500FP ISA

```
Layer 3:  Application objects
          (FlowCode graphs, GUI widgets, P2PCP node addresses, CGP tokens,
           MMID/MMOE meshes)

Layer 2:  TernOO word interpreter   ← this specification
          (2+4+18 word format, nine primaries, OPCODE IR, WORD_OP dispatch,
           GristMill TTree/OTree synthesis)

Layer 1:  5500FP ISA                ← stable substrate
          (fetch-decode-execute, 81 registers, balanced-ternary instruction set)
```

The word interpreter runs on the 5500FP; the ISA is not modified. The WORD_OP
family (`TOBJ`, `TGET`, `TPAYLOAD`, `TCALL`, `TNEW`, `TBUILD`, `TSEG`) implements
the Layer-2 dispatcher. The native ternary instruction group (trit decode,
three-way branch, MIN/MAX/TXOR) makes Layer 2 efficient without software
simulation.

## 13. Relationship to TernOO / SBTCVM

SBTCVM established the core insight: the leading trit of a ternary word is the
natural type tag, and three-way dispatch on it is the natural primitive. This spec
extends that to the 5500FP's 24-trit word:

| Property          | SBTCVM TernOO   | 5500FP TernOO (this spec)          |
|-------------------|-----------------|------------------------------------|
| Word width        | 9 trits         | 24 trits                           |
| Primary field     | 1 trit (3 types)| **2 trits (9 types)**              |
| Qualifier         | —               | **4 trits (81 states/primary)**    |
| Payload           | 8 trits         | **18 trits (three ±364 tribbles)** |
| Opcode word       | —               | **OPCODE primary (family+arity+IR)**|
| Object descriptor | via Option A    | self-contained (PTR_USER_DEF)      |
| Content mesh      | —               | **TTree/OTree MMID→MMOE (GristMill)**|

## 14. Evolution — v0.1 (1+3+20) → v0.3 (2+4+18)

| Aspect               | v0.1 fossil (1+3+20)    | v0.3 current (2+4+18)                       |
|----------------------|-------------------------|---------------------------------------------|
| Primary field        | T23 (1 trit)            | **T23–T22 (2 trits)**                        |
| Qualifier            | T22–T20 (3 trits)       | **T21–T18 (4 trits)**                        |
| Payload              | T19–T0 (20 trits)       | **T17–T0 (18 trits, three tribbles)**        |
| Primary types        | 3 (EXEC/MAP/DATA)       | **9** (+ NEURAL, I/O, CRYPTO, OPCODE, OPEN_B, POOL) |
| Qualifier states     | 27 (3³)                 | **81 (3⁴) per primary**                      |
| OPCODE instruction   | absent                  | **present** (6 families, arity chaining, FORM IR) |
| TTree/OTree mesh     | absent                  | **present** (T18 mode_hint; MMID→MMOE fold)  |
| Symbol families      | absent                  | **present** (SHAPE/STYLE/LAYOUT/SIGNAL)      |

**Backward compatibility.** Every legacy EXEC/MAP/DATA word carries T22 = −1, so
the 2-trit primary reads legacy words correctly (their type was T23 alone). MAP's
old T18 "spare" is now the mode_hint. DATA's payload lost its top two trits to the
widened qualifier.

## 15. Open Questions

**Q1.** EXEC addressing — absolute payload vs. a code-segment-base + offset scheme
mirroring `PTR_USER_DEF`'s CODE-SEG tryte.

**Q2.** How many of the 81 registers to allocate as code/data segment-base
registers for `PTR_USER_DEF` and EXEC resolution.

**Q3.** MAP payload semantics per mode — absolute vs. relative vs. scaled, keyed by
the zero-axis count.

**Q4.** A FORMAT word (a reserved type that redefines the qualifier/payload
boundary for a following stream) for domain-specific formats (audio, image,
protocol packets) — while preserving P1.

**Q5.** P2PCP addressing — the `PTR_REMOTE` model vs. a dedicated extended MAP
format for node references.

**Q6.** Activating the dormant primaries: NEURAL (GHOST mesh), I/O (native
filesystem, Stage 10), CRYPTO (`ternary_sponge` / MMID as a security boundary).
